# gbrain lessons for Exponential

**Date:** 2026-10-27 · **Studied:** [garrytan/gbrain](https://github.com/garrytan/gbrain) at `beb49f3278` (v0.60.472.0, MIT), checked out at `~/code/gbrain` · **Status:** research, no code changed

**Frame.** Knowledge in Exponential serves the operating loop (goals → work → shipped) and must not become the category ([strategy doc](2026-08-05-agno-exponential-product-strategy.md) lines 20 and 133). gbrain is the opposite bet: the brain *is* the product, so 162 MCP tools, nightly "dream" cycles and 100K-page corpora follow. Syntrofi dropped it on 2026-10-27 because nobody wrote to it. Every idea below is therefore judged first on: **does it make a human or agent write to, or read from, Exponential while doing their actual work?**

Syntrofi's Fact pages already converge on gbrain's best idea by hand. [Fact: Website (syntro.fi)](https://www.exponential.im/w/syntrofi/pages/cmvqmpje60031k108dneok6p3) has a `Source / As of / Status` line, compiled prose, and a dated `**Timeline**` list at the bottom. That is gbrain's page shape, unenforced.

## Top 3 recommendations

**1. Make "compiled truth + append-only timeline" the page shape, and give agents an append verb.** gbrain splits every page at a `<!-- timeline -->` sentinel: prose above is rewritten as evidence changes, dated entries below are never edited, and every entry carries `[Source: who, channel, date]` (`docs/guides/compiled-truth.md`, `src/core/markdown.ts:337-391`, `docs/guides/source-attribution.md`). The lesson for the "nobody wrote" failure is that *appending a dated line is the only write an agent will reliably make*: it needs no judgement about what to rewrite and cannot damage the page. Exponential's only agent write today is whole-body replace (`mastra.updatePage`, `src/server/api/routers/mastra.ts:4068`; MCP `pages update`). Proposal: a `## Timeline` convention on pages, a `page.appendTimeline` procedure exposed through MCP and CLI that inserts `- **YYYY-MM-DD** | summary [Source: …]` without touching the body, and a Stop-hook or end-of-run step that appends one line per session to the pages it touched (gbrain's `memory.auto_writeback`, `docs/guides/ambient-writeback.md`, but into a timeline a human can read, not a facts table). This is the same work as in-flight gap 4 (source and as-of fields); do them together. Value H, effort S–M.

**2. Hand agent runs a zero-LLM context pack at start, and a "what changed since" delta for repeat runs.** gbrain's `context_pack` and `delta` verbs (`docs/protocol/MEMORY_VERBS_v1.md:893-1060`) are the parts of its hook story worth copying: at session start the agent gets entity cards, open threads and recent facts inside a token budget, built deterministically (`src/core/context/session-start-pack.ts`). Exponential already assembles a run brief (`mastra.getRunContext`, `mastra.ts:973-1068`: action, last 20 comments, members, predecessor summary) but it never includes knowledge. Proposal: extend the brief with the compiled truth of pages linked from the action's project and feature, open Decisions, and the last N timeline entries, capped by budget, plus a `since` parameter so a recurring Assistant run sees only deltas. The planned "Pages home" page is the natural first card. This is the read side of the loop and needs no harness hooks. Value H, effort M.

**3. Make search hybrid inside the agent-search gap, and gate it with a tiny golden-query eval.** `KnowledgeService.search()` is cosine-only (`src/server/services/KnowledgeService.ts:535-720`); the MCP `search` tool is title `contains` only (`exponential-mcp/src/index.ts:620` → `search.global`). gbrain treats keyword + vector + RRF as table stakes, but the wins that matter for a small named-thing corpus are title-phrase boost and an `evidence` / `create_safety` tag on each hit, so an agent knows whether a page already exists before creating a duplicate (`docs/architecture/RETRIEVAL.md` "Named-thing retrieval", `src/core/search/hybrid.ts`). Proposal: add a `tsvector` column on `KnowledgeChunk`, fuse with RRF, boost exact title matches, return `evidence` on every hit, and ship a 20-query `qrels.json` with a recall@5 check in CI (`docs/eval-bench.md`). Value H, effort M. This belongs inside in-flight gap 2, not beside it.

## Don't adopt

- **Takes, hunches, bets and holder weights.** Epistemics for a 100K-page personal brain; Syntrofi has nine company pages.
- **The dream cycle and cron enrichment.** The "brain as product" bet; it makes a brain nobody writes to look alive.
- **Schema packs and 15-type taxonomies.** Exponential's types are Project, Action, Decision, Page; that is the point.
- **162-tool MCP surface and surface ladders.** gbrain found narrowing the surface saved no tokens; the answer is fewer tools, not tiers.
- **Git as system of record.** Syntrofi just left a git-backed brain; ADR sync covers the one case where git is canonical.
- **Memorable, voice, Twilio, email ingestion into pages.** Inputs to a brain, not to a work loop.
- **A bootstrap that owns hooks and a private repo.** Exponential should be reachable from any harness over MCP and CLI, not install itself into one.

## Open questions for James

1. Should timeline appends from agents land directly, or as drafts a human confirms, as agent Decisions do under ADR-0070? Direct is what makes "nobody wrote" go away; drafts are what makes pages trustworthy.
2. Is the Pages home page the right first card of the run context pack, or should it be the project's linked pages only? gbrain prints allowlisted `MEMORY.md` sections at session start; a workspace-wide card risks the 20,000-line CLAUDE.md problem.
3. Who owns `KnowledgeChunk` keyword indexing: this repo's gap 2 work, or a separate ticket? Rec. 3 should not fork the in-flight search design.
4. Do you want `[[Title]]` wikilinks in cloud pages (matching the local Tauri wiki), or only URL links? The link-graph proposal depends on it.
5. The agent's "did it read a page it should have" metric needs run events to record page reads. Is that acceptable telemetry for Syntrofi's workspace?
